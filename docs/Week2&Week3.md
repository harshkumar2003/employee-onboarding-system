# Week 2

## JavaScript, TypeScript & React Basics

## Sprint 2 Goal

### Build the foundational frontend modules for the Employee Onboarding Portal.

### HR4 : Employee List Module

#### User Story:
As an HR/Admin, I want to view all employees in a structured list, so that I can track employee onboarding information.

#### Acceptance Criteria:

- Employee list should display all available employees.
- Employee name should be visible.
- Employee onboarding status should be visible.
- Employee list should be rendered dynamically.
- Employee data should load successfully.

### HR5 : Employee Details Module

#### User Story:
As an HR/Admin, I want to view employee details, so that I can manage employee onboarding activities.

#### Acceptance Criteria:

- Employee details should display employee information.
- Employee details should load dynamically.
- Selected employee information should be displayed correctly.
- Employee information should be easy to access.

### HR6 : Dashboard Navigation

#### User Story:
As an HR/Admin, I want to navigate between dashboard modules, so that I can access onboarding features easily.

#### Acceptance Criteria:

- Dashboard page should load successfully.
- Sidebar navigation should be available.
- Routes should navigate correctly.
- Dashboard layout should be reusable.

# Week 3

## Advanced React

## Sprint 3 Goal

### Build reusable and scalable employee management modules for the onboarding portal.

### HR7 : Employee Management Module

#### User Story:
As an HR/Admin, I want to manage employee onboarding records, so that I can maintain employee information efficiently.

#### Acceptance Criteria:

- HR/Admin can add employees.
- Employee information should be validated.
- Employee data should appear in the employee list.
- Required fields should not be empty.
- Employee onboarding status should be visible.

### HR8 : Employee Form Validation

#### User Story:
As an HR/Admin, I want proper validation on employee forms, so that incorrect information cannot be submitted.

#### Acceptance Criteria:

- Full Name is required.
- Email should follow proper format.
- Phone Number should be validated.
- Joining Date should be validated.
- Error messages should be displayed.

### HR9 : Reusable UI Components

#### User Story:
As a Developer, I want reusable UI components, so that I can reduce duplicate code and improve maintainability.

#### Acceptance Criteria:

- Reusable Table Component should be implemented.
- Reusable Button Component should be implemented.
- Reusable Modal Component should be implemented.
- Search Component should be implemented.
- Layout components should be reusable.
